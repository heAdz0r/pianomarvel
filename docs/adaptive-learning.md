# Adaptive MusicXML — музыкальный компилятор практики

Adaptive превращает MusicXML не в равномерную «нарезку по N тактов», а в
иерархический маршрут разучивания:

```text
MusicXML → Phrase → Bridge → Review → Summarize 1/3–3/3 → Whole
```

Алгоритм универсален: в нём нет правил для конкретного файла, названия
композиции или заранее известных номеров тактов. Все границы выводятся из
партитуры и проверяются одинаковыми педагогическими инвариантами.

## Почему нотной разметки недостаточно

Аудит корпуса из 18 уникальных партитур показал, что признаки, на которые
опирается «выразительный» слой, доступны в единицах файлов:

| признак | в скольких партитурах |
|---|---|
| `rall.` / `rit.` / `a tempo` словами | 3 из 18 |
| лиги | 6 из 18 |
| ферматы, цезуры, breath-mark | 0 из 18 |
| формальные метки (rehearsal, segno, repeat, ending) | 7 из 18 |
| гиперметрическая периодичность | 18 из 18 |
| дословные повторы блоков | 12 из 18 |
| пауза в мелодическом потоке | 14 из 18 |
| `<pedal>` | 9 из 18 (до 312 событий) |
| `<metronome>` | 16 из 18 |

Поэтому форма, метр и фразовые окончания выводятся из самой музыки — высот,
ритма, гармонии и повторности, — а нотная разметка используется как более
надёжное, но не обязательное подтверждение.

## Восемь слоёв анализа

| Слой | Что читается | Как влияет на маршрут |
|---|---|---|
| **L0 Notation form** | репризы, вольты, rehearsal, двойные черты, segno/coda, смены размера и ключа | жёстко фиксирует авторские границы разделов |
| **L1 Melodic surface** | ведущий поток, LBDM по интервалам/IOI/паузам, пауза мелодии, приход на долгую ноту | даёт фразовые окончания там, где нотация молчит |
| **L2 Harmony** | тональность (Krumhansl–Kessler), аккордовые корни по шаблонам, гармонический ритм, каденции PAC/IAC/half/plagal | закрытие фразы определяется каденцией, а не числом тактов |
| **L3 Repetition / Form** | матрица самоподобия по тактам, новизна ядром-шахматкой (Foote), максимальные дословные и нечёткие повторы, граф секций A/A′/B | находит куплет, припев, репризу и вторую половину пьесы |
| **L4 Meter / Hypermeter** | период **и фаза** гиперметра, оценённые совместно; внутри раздела фаза уточняется | границы совпадают с сеткой пьесы вместо правила «каждые четыре такта» |
| **L5 Motor / Ergonomics** | нагрузка на музыкальное время, растяжка аккорда, полиритм между руками, чёрные клавиши, перекрещивание рук, скидка за уже освоенный материал | выравнивает реальную трудность, а не длину такта |
| **L6 Expression** | tempo-жесты, `<metronome>` и `<sound tempo>` с порогом относительного изменения, динамика, педаль, артикуляционные режимы | сохраняет направленные жесты и не принимает playback-рубато за смену темпа |
| **L7 Navigation** | развёртывание реприз, вольт, `D.S.`, `D.C.`, `To Coda` | упражнение никогда не сшивает то, что в исполнении не звучит подряд |

## Информативность вместо абсолютных порогов

Один и тот же признак в разных партитурах значит разное. В *Another Love* tie
переносится через 97 тактовых черт из 120 — там запрет резать внутри tie
бессмыслен; в *The Unforgiven* ties нет вовсе. Поэтому каждый тип сигнала
получает вес по собственной информативности в этой партитуре:

```text
ι = log(1 / p) / log(N),   p — доля тактов, где признак срабатывает
```

Признак, срабатывающий почти везде, теряет вес автоматически; редкий —
усиливается. Так же нормируются сила границы и наличие закрытия: сравнение идёт
с внутрипьесным распределением (верхний дециль), а не с фиксированным числом.
Именно это позволило отказаться от порогов «балл ≥ 3» и «балл ≥ 4».

## Учебная иерархия

### 1. Phrase — целая музыкальная мысль

Динамический оптимизатор выбирает все границы совместно. В цене фрагмента
участвуют: отсутствие музыкального закрытия, несовпадение с гиперметрической
сеткой, пересечение шва формы, пересечение разрыва порядка исполнения, разрез
внутри tie / tempo-жеста / динамической дуги / лиги (со своей информативностью),
баланс моторной нагрузки и отклонение от целевой длительности на Slow.

Вместо награды за каждую границу используется **штраф за слабую границу**: с
богатым набором признаков награда делала выгодным резать чаще, и фраза
рассыпалась на четырёхтактовые обрывки.

### 2. Bridge — переход как самостоятельный навык

Bridge создаётся на каждом стыке соседних Phrase и на внутренних переходах.
Таксономия переходов (ASCII-код в заголовке упражнения):

| код | переход | статус |
|---|---|---|
| `meter` | смена размера | обязательный |
| `nav` | навигационный прыжок: вольта→вольта, `To Coda`, `D.S.`, реприза | обязательный |
| `stop` | возобновление после ферматы, цезуры или полной паузы | обязательный |
| `tempo` | вход в `rall./rit./accel./stringendo/rubato`, возврат `a tempo`, численная смена темпа | обязательный |
| `key` | модуляция | по уязвимости |
| `hands` | смена ключа `<clef>`, `8va`, перенос регистра | по уязвимости |
| `poly` | смена ритмического деления, полиритм | по уязвимости |
| `artic` | смена штриха | по уязвимости |
| `pedal` | смена педализации | по уязвимости |
| `tech` | арпеджио, глиссандо | по уязвимости |
| `orn` | вход в орнамент, трель, тремоло | по уязвимости |
| `voices` | смена плотности голосов и аккордов | по уязвимости |
| `dyn` | резкая смена динамики | по уязвимости |
| `texture` | смена фактуры внутри раздела | по уязвимости |

Порог уязвимости считается по всем стыкам тактов этой партитуры (медиана + MAD),
а необязательные переходы отбираются от самых уязвимых, чтобы список остался
учебным маршрутом.

### 3. Review — несколько уже цельных Phrase

Review объединяет полные Phrase и закрывается по **разделу формы** — не только
по метке нотации, но и по шву, выведенному из повторности и новизны. Граница
Phrase никогда не режется ради Review.

### 4. Summarize — три музыкальные части

Две границы выбираются совместно только между Phrase, с приоритетом шва формы и
закрытия и с запретом разрывать дословно повторяющийся блок. Поэтому доли могут
быть `30% / 37% / 33%`, если так музыкально естественнее.

## Инварианты Piano Marvel

- **Chopped** содержит только двуручные Phrase, Bridge, Review и Summarize.
- **Minced** строится из Chopped и получает combined / RH / LH варианты.
- **Whole** содержит полную пьесу и варианты рук.
- Phrase полностью и непрерывно покрывают диапазон Whole.
- Каждый стык соседних Phrase покрыт Bridge.
- Review и Summarize состоят только из целых Phrase.
- Диапазон тактов MusicXML обязан совпадать с Whole; небезопасное автоматическое
  смещение запрещено.
- Phrase не пересекает разрыв порядка исполнения; если короткая вольта не
  образует самостоятельного непрерывного диапазона, выдаётся warning, а стык
  закрывается отдельным Bridge.

## Пересборка всегда полная

Кнопка «Обновить» удаляет схему и собирает её заново текущим алгоритмом. Раньше
сброс делался только при статусе не «ok», и это было неверно: изменившаяся
музыкальная логика даёт другие границы, а прежняя схема формально остаётся
«полной» — обновление ничего не переделывало. Заодно Minced теперь пересоздаётся,
когда границы Chopped изменились, а не только когда вкладка пуста.

Сервер запускается без watch (`bun run server/index.ts`), поэтому **после правки
музыкальных модулей процесс нужно перезапустить** — иначе в памяти остаётся
прежняя версия алгоритма. Проверить, какая версия отработала, можно по логу задачи:
он печатает подпись плана — гиперметр, метрики и список границ Phrase.

### Готовность вкладки — состояние, а не потолок ожидания

Готовность вкладки раньше определялась равенством «число отрисованных `.exercise`
= число упражнений в хранилище». На длинном списке это условие недостижимо: Piano
Marvel рисует окно видимых строк, и в Minced на 156 упражнений в DOM остаётся
около десяти. Ожидание всегда доходило до аварийного потолка в 30 секунд, и шаг
падал уже после того, как схема была собрана.

Теперь:

- вкладка готова, когда она активна, есть кнопка Save и список соответствует
  хранилищу по признаку «пусто / непусто»;
- шагу темпов список не нужен вовсе — его условие готовности это три поля BPM;
- шаг темпов идемпотентен: если хранилище уже содержит целевые значения, UI не
  трогается, а признаком завершения ввода служат значения в полях, а не включение
  кнопки Save (Piano Marvel оставляет её выключенной, когда значение не изменилось);
- полноту сохранённого по-прежнему проверяет `verifyExercisesVisible`, но его
  аварийный потолок растёт вместе с длиной списка — плоский потолок в таком месте
  сам становится механизмом ожидания;
- падение шага не отменяет результат: аварийная ветка перепроверяет схему теми же
  критериями (остаток плана плюс строгое соответствие цели) и принимает её, если
  она уже собрана.

## Гарантии универсальности

`server/adaptive-guarantees.test.ts` проверяет не музыкальный результат, а способ
его получения:

- в исполняемом коде нет названий произведений, композиторов и путей к файлам;
- нет условий вида «такт === N»;
- каждая константа `PEDAGOGY` документирована (первый прогон нашёл десять без
  обоснования);
- один и тот же MusicXML даёт один и тот же план;
- правка одного такта не сдвигает границы в другом конце партитуры;
- метрики устойчивы к изменению темпа разучивания на ±25 %.

## Проверка качества

Инварианты и музыкальные метрики считает `server/adaptive-corpus-audit.ts`
вместе с `server/adaptive-quality.ts` на 20 MXL-путях / 18 уникальных
партитурах. Метрики и текущие значения — в
[docs/adaptive-quality-report.md](adaptive-quality-report.md):

- **closureRate** — доля границ Phrase с музыкальным закрытием;
- **hypermeterAlignment** — доля границ на гиперметрической опоре;
- **sectionRecall** — доля швов формы, ставших границей Phrase;
- **durationCv** — разброс длительностей Phrase внутри пьесы;
- **forcedCutRate** — доля разрезов внутри значимого жеста;
- **navigationBreaks** — Phrase поверх разрыва порядка исполнения;
- **boundaryPrecision / mandatoryRecall** — сравнение с экспертной аннотацией
  `server/fixtures/phrase-ground-truth.json` с допуском ±1 такт.

## Методическая база

1. [W3C MusicXML 4.0 — direction](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/direction/)
   задаёт семантику tempo/dynamic directions, педали, метронома, барлайнов и
   навигации.
2. [Cambouropoulos, *The Local Boundary Detection Model (LBDM)*](https://www.ofai.at/papers/oefai-tr-2001-11.pdf) —
   локальные границы по изменению интервала, IOI и паузы; веса профилей
   0.25 / 0.5 / 0.25.
3. [Cambouropoulos, *Musical Parallelism and Melodic Segmentation*](https://www.researchgate.net/publication/277386111_Musical_Parallelism_and_Melodic_Segmentation) —
   повторность как самостоятельный признак границы.
4. [Foote — self-similarity и новизна](https://www.researchgate.net/publication/200806134_Visualizing_Musical_Structure_and_Rhythm_via_Self-Similarity) —
   матрица самоподобия и ядро-шахматка для швов формы.
5. [Barwise Section Boundary Detection in Symbolic Music](https://arxiv.org/html/2509.16566v1) —
   границы разделов по тактам в символьной музыке.
6. [Cadence Detection in Symbolic Classical Music](https://arxiv.org/abs/2208.14819) —
   каденция требует совместного учёта гармонии, голосоведения и ритма.
7. [Caplin — период и каденция как конец фразы](https://en.wikipedia.org/wiki/Period_%28music%29)
   и [классификация типов тем](https://jameshepokoski.com/wp-content/uploads/2021/07/2020-rev.-from-2006-2008-The-Classification-of-Theme-Types-Period-Sentence-Hybrid-.pdf).
8. [Chuan & Chew, *A Dynamic Programming Approach to the Extraction of Phrase Boundaries*](https://kclpure.kcl.ac.uk/portal/en/publications/a-dynamic-programming-approach-to-the-extraction-of-phrase-bounda/) —
   совместная оптимизация границ; не всякое замедление является концом фразы.
9. [Chaffin & Imreh, *Practicing Perfection*](https://musiclab.uconn.edu/wp-content/uploads/sites/290/2013/10/Practicing-Perfection-Chaffin-2002.pdf)
   и [*Seeing the Big Picture*](https://production.wordpress.uconn.edu/musiclab/wp-content/uploads/sites/290/2013/10/Seeing-the-Big-Picture-Piano-Practice-as-Expert-Chaffin-2003.pdf) —
   формальная структура как схема извлечения и performance cues.
10. [Shih, Hirano & Furuya, *Bridging chunks during complex movement sequence execution*](https://pmc.ncbi.nlm.nih.gov/articles/PMC12816802/) —
    повышенная уязвимость стыков и польза junction-specific practice.
11. [Blocked vs interleaved practice в музыкальном обучении](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4989027/) —
    обоснование вариантных Review.
12. [Guerino Mazzola, *The Topos of Music I*](https://link.springer.com/book/10.1007/978-3-319-64364-9) —
    структурная линза: мотив, форма и жест как связанные уровни.

## Где находится реализация

- `server/adaptive-notes.ts` — нотная модель: события с музыкальным временем,
  потоки, длительности тактов, объединение партий.
- `server/adaptive-melody.ts` — ведущий поток, LBDM, пауза мелодии.
- `server/adaptive-harmony.ts` — тональность, аккордовые слоты, каденции.
- `server/adaptive-structure.ts` — самоподобие, новизна, повторы, граф секций,
  гиперметр.
- `server/adaptive-navigation.ts` — граф порядка исполнения.
- `server/adaptive-learning.ts` — сборка контекста, информативность сигналов,
  динамическая оптимизация Phrase, Bridge, Review, Summarize и confidence.
- `server/adaptive-quality.ts` — музыкальные метрики плана.
- `server/fixtures/phrase-ground-truth.json` — экспертная аннотация границ.
- `server/learning-adaptive-page.ts` — применение плана к Chopped.
- `server/learning-plan.ts` — целевая схема Whole / Chopped / Minced.
- `server/adaptive-learning.test.ts`, `server/adaptive-musicality.test.ts` —
  регрессионные и музыкальные тесты.
- `server/adaptive-corpus-audit.ts` — проверка на реальных партитурах.
