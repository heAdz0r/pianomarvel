# PRD: Adaptive MusicXML 2.0 — эталонный музыкальный компилятор практики

Статус: **реализовано** (фазы P0–P4). Результаты замеров — в
[docs/adaptive-quality-report.md](adaptive-quality-report.md), описание текущего
алгоритма — в [docs/adaptive-learning.md](adaptive-learning.md). Фаза P5
(внутритактовые границы через `startTick > 1`) не реализована: она требует
отдельной live-валидации контракта Save в Piano Marvel.

Автор анализа: аудит кода `server/adaptive-learning.ts` (2092 строки на момент
анализа) + прогон 20 путей / 18 уникальных партитур + прототип недостающих
сигналов + сверка с музыкальной теорией и MIR-литературой.

Правило номер один: **никакого хардкода**. Ни одного правила по названию пьесы,
номеру такта, жанру или ожидаемому числу упражнений. Любая константа либо выводится
из партитуры, либо живёт в `PEDAGOGY` с музыкальным обоснованием и тестом
чувствительности.

---

## 1. Проблема

Текущий алгоритм проходит все инварианты Piano Marvel (аудит 20 путей = OK), но
**музыкально он всё ещё близок к равномерной нарезке** на тех партитурах, где в
MusicXML нет разметки формы. Причина структурная: все четыре слоя (Form, Expression,
Motor, Mapping) читают *нотацию*, и почти ничего не читают *музыку* — высоты, гармонию,
повторность, гиперметр. Когда экспортёр не поставил repeat/rehearsal/slur/`rall.`,
сигналов не остаётся, и границы определяет только баланс «нагрузки» плюс правило
`(index + 1) % 4 === 0`.

### 1.3 Дефекты реализации, найденные при чтении кода

1. `(index + 1) % PEDAGOGY.fallbackPhraseMeasures === 0` — единственная «метрическая
   опора» жёстко зашита на период 4 и **фазу 0**. Затакт, 3-дольные и 6- / 8-тактовые
   периоды сдвигают фазу, и опора начинает работать против музыки.
2. `load` — на такт, не на музыкальное время. При сменах размера и на 3/8 сравнение
   тактов некорректно (см. Nothing Else Matters).
3. `<sound tempo>` трактуется как смена темпа без порога относительного изменения;
   playback-рубато превращается в формальные границы (5 баллов) и в лишние
   `internalTempoCandidates` → Bridge. `<metronome>` не парсится вовсе.
4. `fullRest` требует тишины во **всех** партиях; пауза только в мелодии (самый частый
   признак конца фразы, 14 из 18 партитур) не детектируется.
5. `motifFingerprint` берёт `staff 1 / voice 1` из *объединённого* такта всех партий и
   требует **точного** совпадения интервалов; поэтому Another Love даёт 0 повторов, а
   Moonlight не видит собственную репризу. Вес возврата мотива = 1 балл.
6. Порог `boundaryScoreAfter >= 4` (`structuralSignals`) и `>= 3`
   (`phraseBoundaryScore`) — абсолютные, при том что шкала баллов у разных партитур
   заполнена по-разному.
7. В `<dashes type="stop">` один и тот же id пишется и в `expressiveTempoStops`, и в
   `dynamicGestureStops` — dashed `cresc.` способен закрыть tempo-span и наоборот.
8. `mapping: "high"` — константа; уверенность отображения ничем не проверяется.
9. Не парсится: `<pedal>`, `<metronome>`, `<clef>` внутри пьесы, `<arpeggiate>`,
   `<glissando>`, артикуляции, `<print new-system>`, `<harmony>`, `<measure-style>`.
10. Bridge на швах вольт/`D.S.`/`To Coda` невозможен, потому что весь анализ идёт в
    порядке печати, а не в порядке исполнения.

## 2. Цель и критерии успеха

**Цель.** Adaptive должен резать партитуру там, где её разрезал бы преподаватель:
по завершениям (каденция, пауза в мелодии, конец лиги, разрешение педали), по
гиперметрической сетке пьесы, по границам формы, выведенным из повторности — и
только потом по балансу нагрузки и по секундам на медленном темпе.

**Измеримые критерии (эталон).** Вводим `server/adaptive-quality.ts` и считаем на всех
20 путях:

| # | метрика | как считается | цель |
|---|---|---|---|
| M1 | Closure rate | доля концов Phrase, где есть событие закрытия (каденция / пауза в мелодии / конец лиги / снятие педали / фермата / формальная метка) | ≥ 0.80 |
| M2 | Hypermeter alignment | доля границ Phrase, попадающих на гиперметрический сильный такт, когда уверенность периода ≥ 0.7 | ≥ 0.85 |
| M3 | Section recall | доля границ секций (SSM-новизна, начало точного повтора, навигационное событие), совпавших с границей Phrase | 1.00 |
| M4 | Duration discipline | коэффициент вариации длительностей Phrase в пьесе на Slow | ≤ 0.35 |
| M5 | Forced-cut rate | доля границ, поставленных внутри tie / tempo-span / лиги | ≤ 0.02 |
| M6 | Navigation safety | число упражнений, пересекающих навигационный разрыв (вольта 1 → вольта 2, `To Coda`, `D.S.`) | 0 |
| M7 | Boundary F1 | против ручной экспертной аннотации на подкорпусе (≥ 6 партитур, допуск ±1 такт) | ≥ 0.85 |
| M8 | Stability | тот же файл → тот же план; правка ≤ 2 тактов меняет ≤ 2 границы | 100 % / bounded |

Базовая линия сегодня (замер до изменений — часть Phase 0): M1 ≈ 0.3–0.5, M2 не
считается, M3 нарушается (Clocks, Gymnopédie), M4 до 0.6 (Another Love), M5 до 0.21
(Another Love), M6 > 0 (Radioactive), M7 не существует.

**Non-goals.** Аудио-анализ; обучаемые модели, требующие датасета; изменение
инвариантов Piano Marvel (Chopped только двуручный, Minced из Chopped, ровно три
Summarize, непрерывное покрытие); любые правила по названию произведения.

## 3. Целевая архитектура

```text
MusicXML
  ├─ L0 Notation form      репризы, вольты, rehearsal, черты, segno/coda, key/time
  ├─ L1 Melodic surface    поток мелодии, LBDM (интервал/IOI/пауза), пауза в мелодии
  ├─ L2 Harmony            тональность, аккордовые корни, гармонический ритм, каденции
  ├─ L3 Repetition/Form    SSM по такту, новизна Foote, точные и нечёткие повторы → граф секций
  ├─ L4 Meter/Hypermeter   период + фаза, затакт, локальная переоценка по секциям
  ├─ L5 Motor/Ergonomics   нагрузка на музыкальное время, растяжка, полиритм, педаль, ключи
  ├─ L6 Expression         tempo/dynamic жесты, metronome, артикуляционные режимы
  └─ L7 Navigation         разворачивание повторов → порядок исполнения (граф)
        │
        ▼
  Salience normalization (устраняет абсолютные пороги)
        ▼
  DP-оптимизатор Phrase → Bridge (таксономия переходов) → Review (по графу секций)
        → Summarize (по графу секций) → Whole
```

### 3.1 L1 — мелодический поток и локальные границы (LBDM)

**Выделение мелодического потока.** Универсальная эвристика без хардкода: для каждой
`(part, staff, voice)` считаем долю тактов, где поток содержит самый верхний
звучащий голос, и монофоничность. Мелодический поток — argmax; остальные потоки
получают роль accompaniment. Так же отделяется вокальная партия в piano+vocal
экспортах (в корпусе такие есть: `Piano, Inst 1`).

**LBDM** (Cambouropoulos): для каждого параметрического профиля
x ∈ {абсолютный интервал высоты, IOI, длительность паузы}

```
r_i    = |x_i − x_{i+1}| / (x_i + x_{i+1})        (0, если сумма = 0)
s_i    = x_i · (r_{i−1} + r_i)
S_x    = s / max(s)                                 нормализация в [0,1]
S_LBDM = 0.25·S_pitch + 0.5·S_ioi + 0.25·S_rest
```

Профиль считается по нотам, затем агрегируется на позиции тактовых черт (и, в фазе 5,
на внутритактовые позиции). Это даёт непрерывный, всегда доступный сигнал границы
там, где сейчас 0 сигналов (Clocks, Moonlight).

**Пауза в мелодическом потоке.** Отдельный сигнал: суммарная пауза мелодии в конце
такта ≥ 1/2 доли такта → сильный признак конца фразы; ≥ целого такта → признак
границы секции (Gymnopédie m.1-4 и m.40-43 — вступления; Moonlight m.5, 9, 15…).

### 3.2 L2 — гармония и каденции

`<harmony>` в корпусе нет ни в одном файле, поэтому гармонию выводим из высот.

1. **Тональность.** Профиль длительностей 12 классов высот; корреляция с
   мажорным/минорным профилем Krumhansl–Kessler по 12 поворотам; `<key><fifths>` —
   априор. Скользящее окно (8 тактов, шаг 1) даёт локальную тональность и модуляции.
2. **Гармонический ритм и корни.** Слот = доля или полтакта (выбирается по частоте
   смены pc-множества); для слота — сопоставление шаблонов {maj, min, dom7, halfdim,
   dim, sus} по 12 корням с весом по длительности и с приоритетом басовой ноты. Выход:
   последовательность (корень, качество, инверсия, длительность слота).
3. **Каденция.** Взвешенный скор в точке прибытия b:

```
cad(b) = w_root ·[движение корня V→I, vii→I, IV→I, V→vi в локальной тональности]
       + w_bass ·[бас приходит на устойчивую ступень, основной вид]
       + w_metr ·[прибытие на сильную долю / начало такта]
       + w_mel  ·[мелодия приходит на 1/3/5 и длится ≥ доли]
       + w_hr   ·[замедление гармонического ритма: слот ≥ 2× медианы]
       + w_ioi  ·[рост IOI и нисходящий контур перед b]
       − w_cont ·[фактура продолжается без разрыва]
```

Классификация: PAC / IAC / half / plagal / нет — с разным весом закрытия. Именно это
восстанавливает границы Moonlight (m.9, 15, 23…) и Gymnopédie (4-тактовые периоды),
где нотация молчит. Теоретическая рамка — Caplin: период = 4+4 с более сильной
каденцией в консеквенте; фраза заканчивается каденцией, а не «через 6 тактов».

### 3.3 L3 — повторность и граф секций

- Признак такта: `chroma(12) ⊕ bass-pc(12) ⊕ гистограмма ритма онсетов ⊕ регистр/фактура`.
- SSM `S_ij = cos(f_i, f_j)`; новизна — ядро-шахматка Foote с размером `L = 2·p`
  (p — гиперметрический период, § 3.4); пики новизны → кандидаты границ секций.
- **Точные и нечёткие повторы.** Точные — хеш окна длиной p (уже даёт 52 повтора в
  Clocks, 30 в Gymnopédie, 20 в Radioactive). Нечёткие — окно с порогом
  `cos ≥ θ`, где θ выводится как квантиль распределения сходства этой пьесы
  (не константа). Это ловит Another Love, где точных повторов 0 из-за разной вязки ties.
- Выход — **граф секций**: интервалы + метки классов (A, A′, B…) + сила шва.
  Используется в Phrase (штраф за пересечение шва), Review (собирает целые секции) и
  Summarize (запрет резать блок точного повтора: Gymnopédie 1-39 / 40-78).

### 3.4 L4 — гиперметр: период И фаза

Вместо `% 4`:

```
для p ∈ {2,3,4,6,8}, φ ∈ [0,p):
  score(p,φ) = mean_i sim(m_i, m_{i+p})
             + λ · mean_{i ≡ φ (mod p)} accent(i)
accent(i) = бас-онсет + смена гармонии + смена динамики/педали + LBDM-пик + новизна
p*, φ* = argmax;  confidence = (score₁ − score₂) / score₁
```

Период переоценивается **внутри каждой секции** (после нерегулярного бриджа фаза
сдвигается — это норма в поп-музыке). Затакт (`implicit=yes`, `number=0`) сдвигает φ
автоматически, а не обрабатывается отдельным условием. Если confidence низкая,
гиперметрический член в цене границы ослабляется — вместо того чтобы навязывать 4.

### 3.5 L5 — моторная нагрузка на музыкальном времени

- `load` нормируется на **музыкальное время такта** (или на секунды при известном
  темпе), а не «на такт». Устраняет искажение при 13 сменах размера.
- Добавить: растяжку в аккорде (интервал > октавы), полиритм между руками
  (соотношение подразделений RH/LH ≠ 1), долю чёрных клавиш, смену `<clef>`,
  `<arpeggiate>` / `<glissando>`, плотность педали, число одновременных голосов в одной
  руке, перекрещивание рук.
- **Новизна как цена обучения.** Стоимость освоения такта уменьшается, если его
  материал уже встречался (L3): четвёртое повторение остинато не требует такого же
  внимания, как первое. Это делает Phrase короче на новом материале и длиннее на
  повторном — именно так и режет преподаватель. Инвариант полного покрытия сохраняется.

### 3.6 L6 — выразительность, включая то, что сейчас теряется

- `<metronome>` (есть в 16 из 18) наравне с `<sound tempo>`; **порог относительного
  изменения** (например ≥ 5 % и не рубато-паттерн) — иначе playback-рубато Gymnopédie
  снова создаст ложные границы.
- `<pedal>` start/stop/change: снятие педали — прямой признак гармонического и
  фразового шва (доступно в 9 из 18, до 312 событий).
- Артикуляционные режимы: скользящая доля staccato/accent/tenuto; смена режима — переход,
  а не граница фразы (Lumière 775 staccato, Love Story 245).
- `<print new-system>` — слабый (вес < метрической опоры) сигнал: гравёр часто ломает
  систему по фразе. Присутствует во всех 18 файлах.

### 3.7 L7 — порядок исполнения (разворачивание навигации)

Строим граф исполнения: forward/backward repeat, `<ending>` (вольты), `D.S.`, `D.C.`,
`To Coda`, `Fine`, `<sound dalsegno/tocoda/fine>`. Из него:

- **Запрет**: Phrase (и Review, и Summarize) не может пересекать навигационный разрыв —
  например включать вольту 1 и вольту 2 подряд (сегодня Radioactive 17-24 нарушает).
- **Bridge на шве исполнения**: для каждого перехода в графе создаётся пара упражнений
  «выход» (такты перед прыжком) и «вход» (такты после посадки), помеченных типом.
  Диапазон Piano Marvel непрерывен, поэтому склеить прыжок одним упражнением нельзя —
  но обе его половины обязаны быть отдельными навыками.

### 3.8 Salience normalization — механизм против абсолютных порогов

Для каждого типа сигнала t считаем частоту срабатывания `p_t = fires / barlines` и
информативность

```
ι_t = clamp01( log(1 / max(p_t, 1/N)) / log(N) )
S(b) = Σ_t  w_t · ι_t · s_t(b),      затем S нормируется на максимум по пьесе
```

Сигнал, срабатывающий почти на каждой черте (ties в Another Love, «возврат мотива» в
остинато Clocks), автоматически теряет вес; редкий и потому информативный —
усиливается. То же для запретов: `tieCutPenalty` умножается на `ι_tie`, поэтому
в Another Love tie перестаёт быть «аварийным разрезом с warning», а в The Unforgiven
остаётся жёстким. Это устраняет пороги `>= 3` / `>= 4` и делает шкалу сопоставимой
между партитурами.

### 3.9 Цена сегмента в DP

Все члены нормированы в [0,1], веса именованы в `PEDAGOGY`:

```
cost(s,e) = α·|log(load/targetLoad)|
          + β·durationBand(seconds)            вне [minChunkSeconds, maxChunkSeconds]
          + γ·(1 − closure(e))                 каденция/пауза/лига/педаль/форма
          + δ·hypermeterMisalign(e) · conf(p*)
          + ε·crossedSectionBoundaries(s,e)
          + ζ·forcedCut(e) · ι_t
          + η·noveltyLoad(s,e)                 новый материал → короче
          − reward·closureStrength(e)
```

Глобально добавляется член дисперсии длительностей (M4) — DP по префиксам с
квадратичным штрафом отклонения от медианной длительности пьесы.

### 3.10 Таксономия переходов для Bridge («не только rall»)

Bridge остаётся обязательным на каждом стыке Phrase, но список триггеров расширяется —
каждый со своим правилом определения из MusicXML и своей меткой в заголовке:

| # | тип перехода | детекция | окно |
|---|---|---|---|
| 1 | шов секции | граф секций L3 / формальная метка | по музыкальному времени, обе стороны |
| 2 | каденция → новая мысль | L2 PAC/HC + начало нового мотива | обе стороны |
| 3 | вход в tempo-жест | `rall./rit./accel./string./allarg./rubato/calando/morendo` (dashed и без) | весь жест, если короткий |
| 4 | возврат `a tempo` | `isTempoReset` + конец span | конец жеста + вход |
| 5 | численная смена темпа | `<metronome>` / `<sound tempo>` с порогом ≥ 5 % | обе стороны |
| 6 | смена размера | `<time>` | обе стороны, обязательно |
| 7 | модуляция / смена ключа | `<key>` или скачок локальной тональности L2 | обе стороны |
| 8 | смена фактуры аккомпанемента | скачок текстурных признаков SSM | обе стороны |
| 9 | перенос регистра / рук | `<octave-shift>`, `<clef>`, большой скачок, перекрещивание | обе стороны |
| 10 | смена плотности голосов / аккордов | Δvoices, ΔmaxChordSize | обе стороны |
| 11 | вход в полиритм | смена режима `<time-modification>` между руками | обе стороны |
| 12 | смена артикуляции / педали | доля staccato·accent, `<pedal>` вкл/выкл | обе стороны |
| 13 | динамический экстремум | Δуровня ≥ 2 ступени, `sfz`, конец hairpin с прибытием | обе стороны |
| 14 | навигационный прыжок | L7: вольта→вольта, `To Coda`, `D.S.`, backward repeat | пара «выход»+«вход» |
| 15 | возобновление после остановки | фермата, цезура, breath-mark, `senza misura` | вход после остановки |
| 16 | вход в орнамент/тремоло/арпеджио | `<trill>`, `<tremolo>`, `<arpeggiate>`, `<glissando>` | обе стороны |

Отбор: обязательные (1, 6, 14, 15) + все, чья уязвимость выше внутрипьесного порога
(медиана + MAD, как сейчас). Дедупликация по совпадению окна остаётся.

### 3.11 Review и Summarize по графу секций

- Review собирает **целые секции**; если секция короче `minReviewMeasures`,
  присоединяется соседняя того же класса. Пары A/A′ предпочтительны — вариантное
  сопоставление даёт контекстную интерференцию (interleaving), а не механическое
  повторение.
- Summarize: две границы выбираются на швах графа секций с максимальной силой закрытия
  при ограничении доли 18–48 %; **запрещено разрывать блок точного повтора**
  (Gymnopédie обязан получить шов 39/40).

## 5. Гарантии «без хардкода»

1. Тест-линтер: падает, если в `server/adaptive-*.ts` встречается название
   произведения, имя файла или литеральный номер такта в условии.
2. Каждая константа `PEDAGOGY` обязана иметь (а) музыкальное обоснование в комментарии,
   (б) тест чувствительности: ±25 % не должно менять метрики M1–M6 более чем на 5 %.
   Константа, проваливающая тест, — скрытый хардкод и должна выводиться из партитуры.
3. Валидация leave-one-out: пороги, выводимые статистически, считаются только по
   текущей партитуре (внутрипьесные квантили), никогда по корпусу.
4. Корпусный аудит остаётся обязательным гейтом; дубликаты по SHA-256 не считаются
   дополнительными примерами (в наборе 20 путей — 18 уникальных партитур).

> Порядок уровней в маршруте, разбор качества разбиения с позиции музыкальной школы
> и каталог оставшихся проблем — в [adaptive-pedagogy-prd.md](adaptive-pedagogy-prd.md).

## 6. Риски

| риск | смягчение |
|---|---|
| Контракт Piano Marvel: только непрерывный диапазон тактов, сортировка по позиции, `start_tick=1` | Навигационные прыжки покрываются парой упражнений, а не одним; P5 за флагом и только после live-проверки |
| Переобучение под 18 партитур | Пороги — внутрипьесные квантили; leave-one-out; запрет корпусных констант |
| Рост стоимости анализа (SSM O(n²)) | n ≤ ~1000 тактов; SSM на признаках такта, не нот; кеш плана по SHA-256 |
| Регресс уже собранных живых пьес | Adaptive применяется при «Перестроить»; отчёт метрик до/после и diff плана по каждой пьесе корпуса |
| Ошибочная гармония на нетональном материале | closure-скор входит с весом, умноженным на уверенность тональности; при низкой уверенности работают L1/L3/L4 |
