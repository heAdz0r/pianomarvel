**Метод:** 12-модульный протокол дизайн-аудита
**Область:** `src/styles/*.css` (8877 строк), `src/App.vue` + 9 компонентов (13 420 строк), `index.html`

## Summary

- Модулей проверено: 12 (включая N/A) | Нарушений: **21**
- **CRITICAL: 4** | **HIGH: 7** | **MEDIUM: 7** | **LOW: 3**
- Аудит выполнен по **отрендеренной** странице (`localhost:5173`, 2099 DOM-узлов), а не только по коду.

### Protected identity — НЕ упрощать, не «причёсывать»

Интерфейс имеет сильный, осознанный швейцарско-редакционный характер. Всё
перечисленное — авторский почерк, findings ниже его не трогают:

1. **Плакатная display-типографика**: Unbounded, `clamp(90px, 10vw, 148px)`, агрессивный
   отрицательный трекинг `-0.075em…-0.09em`. Это подпись, а не ошибка кернинга.
2. **Синие монолиты** `#1557ff` во всю высоту секции с вывороткой.
3. **Space Mono** в uppercase-эйсбро с широким трекингом (`01—03`, `DIGITAL SCORE DESK`).
4. **Нотный фон** `staff-drift` — медленно уплывающие нотные линейки в 28s.
5. **Хореография входа** `rise-in` со ступенчатыми задержками 0.02/0.12/0.2s.
6. **Нумерация шагов** `01`, `02`, `03` как навигационный мотив.

## M1: Signifiers & Grouping

### Subtask M1.1 — Нажатие не подтверждается почти нигде

- **Current:** 194 объявления `:hover` против **32** `:active` во всём проекте.
- **Evidence:** census по `src/styles/*.css` + `src/components/*.vue`; `:focus-visible` — 72.
- **Problem:** M1.3 — каждый интерактивный элемент обязан иметь press-состояние.
  Наведение есть у ~83 % элементов, тактильный отклик на клик — у 16 %. На тачпаде и
  тач-экране hover не существует вовсе, то есть для этих вводов обратной связи нет.
- **Target:** единый утилити-класс поверх токенов:
  ```css
  .pressable { transition: transform var(--d-instant) var(--ease-out), filter var(--d-instant) var(--ease-out); }
  .pressable:active { transform: scale(0.97); filter: brightness(0.94); }
  @media (hover: none) { .pressable:active { transform: scale(0.95); } }
  ```
  Применить ко всем 80 `<button>` и к кликабельным строкам таблицы.
- **Severity:** HIGH

### Subtask M1.2 — Группировка контейнерами соблюдена

- **Current:** `.movement`, `.panel`, карточки таблицы имеют общие фоны и радиусы.
- **Problem:** нарушений нет.
- **Severity:** — (No violations)

## M4: Typography

> Выбор гарнитур **правильный и SoTA-уместный**: Unbounded (display) + Manrope (UI) +
> Space Mono (данные/эйсбро) — три роли, три гарнитуры, все с кириллицей.
> Ниже — не про выбор шрифтов, а про шкалу.

### Subtask M4.1 — 307 видимых элементов мельче 11px, минимум — 7px кириллицей

- **Current:** на отрендеренной странице **307** видимых текстовых элементов имеют
  `font-size < 11px`. Среди них подписи переключателя режима «Основной режим» /
  «Ручной режим» — **7px**. В коде: **60** объявлений мельче 11px
  (`table.css` 26, `awwwards.css` 12, `MuseScoreMovement.vue` 9, `FingeringScore.vue` 4).
- **Evidence:** замер по DOM `localhost:5173`; census по исходникам.
- **Problem:** M4 + severity rubric — текст мельче 11px нечитаем. Для кириллицы порог
  выше латиницы: у строчных «в», «н», «п», «и» при 7–9px различительные признаки
  схлопываются в один штрих. Это не «мелкий акцент», это нечитаемая подпись на
  управляющем элементе.
- **Target:** абсолютный пол **11px**. Пересадить всё, что ниже, на `--text-caption: 11px`
  и `--text-label: 12px`; там, где 11px не помещается — сокращать текст или менять
  вёрстку, а не кегль. Для uppercase Space Mono минимум **11px** с `letter-spacing: 0.08em`.
- **Severity:** **CRITICAL**

### Subtask M4.2 — Около 40 кеглей вместо 6

- **Current:** 21 фиксированный px-кегль + 14 выражений `clamp()` + 6 значений в `em`.
  Токенов кегля в системе — 6 (`--fs-display/num/lead/body/sm/label`), но они покрывают
  меньшинство использований.
- **Evidence:** census `font-size` по всем стилям и компонентам.
- **Problem:** M4.3 — жёсткий лимит 6 размеров. Плотное приложение с таблицами требует
  узкой шкалы (M4.4, максимум 24px в UI-слое), а плакатный герой — отдельной display-шкалы.
  Сейчас обе смешаны в один непрерывный градиент.
- **Target:** две раздельные шкалы, всё остальное запрещено линтером:
  ```css
  :root {
    /* UI-слой — плотность данных, потолок 24px (M4.4) */
    --text-page:    24px;  /* заголовок экрана */
    --text-section: 18px;  /* заголовок секции */
    --text-title:   16px;  /* заголовок карточки/строки */
    --text-body:    15px;  /* основной (= текущий --fs-body) */
    --text-label:   12px;  /* подписи, чипы */
    --text-caption: 11px;  /* минимум, эйсбро Space Mono */

    /* Display-слой — только плакатные заголовки, identity */
    --display-xl: clamp(90px, 10vw, 148px);
    --display-lg: clamp(60px, 6.8vw, 106px);
    --display-md: clamp(34px, 3.7vw, 56px);
  }
  ```
  14 существующих `clamp()` свести к трём display-ступеням.
- **Severity:** **CRITICAL**

### Subtask M4.3 — Микрокоррекция заголовков: соблюдена

- **Current:** `clamp(66px, 8.2vw, 124px)` + `letter-spacing: -0.075em`;
  `clamp(90px, 10vw, 148px)` + `-0.09em`; `64px` + `-0.08em`.
- **Problem:** формально жёстче рекомендации M4.2 (−2…−3 %), но это **осознанный
  редакционный трекинг**, подтверждённый рендером. Нарушением не считается — см.
  Protected identity.
- **Severity:** — (No violations, protected)

### Subtask M4.4 — Мёртвое объявление гарнитур вводит в заблуждение

- **Current:** `foundation.css:37-39` объявляет `--display: "Instrument Serif"`,
  `--ui: "Inter"`. Ни одна из этих гарнитур **не загружается** — `index.html` подключает
  Manrope, Space Mono, Unbounded. Реальные значения приходят из `awwwards.css:43-45`.
- **Evidence:** [foundation.css:37](../src/styles/foundation.css#L37) против
  [awwwards.css:43](../src/styles/awwwards.css#L43) и `index.html`; подтверждено
  `getComputedStyle` — живое значение `--ui` = `"Manrope"`.
- **Problem:** источник истины не совпадает с тем, что читается первым. При изменении
  порядка `@import` в `src/style.css` или при выносе `awwwards.css` в ленивый чанк весь
  интерфейс молча перейдёт на Georgia + system-ui. Сейчас это удерживается только
  порядком строк в одном файле.
- **Target:** удалить `--display`/`--ui`/`--mono` из `foundation.css`; оставить одно
  объявление. См. M5.1 — то же лечится одной операцией.
- **Severity:** HIGH

## M5: Color & Semantic Palette

### Subtask M5.1 — Имена токенов означают противоположное своим значениям

- **Current:** `awwwards.css` перекрывает **46 из 61** токена `foundation.css`, инвертируя
  тему из тёмной в светлую. Имена при этом остались от тёмной:

  | токен | смысл имени | `foundation.css` | **живое значение** |
  |---|---|---|---|
  | `--ink` | чёрные чернила | `#090b15` | **`#f3f7ff`** почти белый |
  | `--ivory` | слоновая кость | `#f2ecdd` | **`#071d50`** тёмно-синий |
  | `--brass` | латунь, золото | `#e4b361` | **`#1557ff`** синий |
  | `--panel` | тёмная панель | `#111629` | **`#ffffff`** белый |

- **Evidence:** `getComputedStyle(document.documentElement)` на `localhost:5173`;
  [foundation.css:2-35](../src/styles/foundation.css#L2) против
  [awwwards.css:2-46](../src/styles/awwwards.css#L2).
- **Problem:** M5.1 — палитра обязана быть единым источником. Здесь их два, второй
  молча побеждает, а имена активно дезинформируют: `background: var(--ink)` даёт белый
  фон, `color: var(--ivory)` — тёмный текст. Любой, кто читает `foundation.css` первым,
  строит неверную модель (при подготовке этого аудита так и произошло).
- **Target:** одна палитра, семантические имена, привязанные к **роли**, а не к материалу:
  ```css
  :root {
    --bg-base: #f3f7ff;  --bg-surface: #ffffff;  --bg-raised: #eef4ff;  --bg-sunken: #dce8ff;
    --fg-strong: #071d50; --fg: #21427f; --fg-muted: #5d73a0; --fg-subtle: #8999ba;
    --accent-300: #7ea4ff; --accent-400: #4f82ff; --accent-500: #1557ff;
    --accent-600: #0b45d8; --accent-700: #07349f;
  }
  ```
  Старые имена оставить алиасами на один релиз, затем удалить. Тёмную палитру
  `foundation.css` не выбрасывать — она нужна в M6.
- **Severity:** **CRITICAL**

### Subtask M5.2 — 203 hex-литерала и 277 rgba() мимо палитры

- **Current:** 232 уникальных hex во всём фронтенде, из них в токенах объявлено 29 →
  **203 вне системы**. Плюс **277** уникальных литералов `rgba()`.
  Рампа `--brass-300…700` существует, но используется 14 раз суммарно, тогда как
  плоский `--brass` — **140** раз.
- **Evidence:** census по `src/styles/*.css` + компонентам.
- **Problem:** M5.1 — вся UI обязана выводиться из рампы. Фактически рампа декоративна:
  оттенки для hover/active/borders берутся ad-hoc литералами, поэтому одинаковые по
  смыслу поверхности в разных секциях имеют разный цвет.
- **Target:** заменить литералы на `--accent-*` / `--bg-*` / `--fg-*`. Прозрачности —
  через `color-mix(in oklch, var(--accent-500) 12%, transparent)` вместо ручной rgba.
  Гейт: тест-линтер падает на новом hex-литерале вне файла палитры (по образцу уже
  существующего линтера `adaptive-guarantees.test.ts`).
- **Severity:** HIGH

### Subtask M5.3 — Нет семантических токенов состояния

- **Current:** `--rose` (18 использований) и `--sage` (6) фактически исполняют роль

  ```css

  --color-error:   #c63e50;  --color-error-bg:   #fff0f2;   /* = текущий --rose */
  ```

### Subtask M5.4 — 153 текстовых узла проваливают контраст WCAG AA

- **Current:** на первом экране **153** узла с контрастом **< 3.0** и 38 в диапазоне
  3.0–4.5. Примеры: эйсбро `быстрый путь` — 1.62; `Загрузить` 13px/800 — 2.40;
  `аккаунт musescore` 9px — 2.87; `Скопируйте адрес страницы` 13px — 2.87.
- **Evidence:** расчёт относительной яркости по всем видимым узлам `localhost:5173`.
- **Problem:** severity rubric — нечитаемый текст. Светлая тема с `--fg-subtle #8999ba`

  два дефекта складываются на одних и тех же элементах.
- **Target:** пересчитать `--fg-muted` / `--fg-subtle` под AA на `--bg-base` и
  `--bg-surface`: `--fg-muted: #4a6390` (4.6:1), `--fg-subtle: #5d73a0` (3.6:1 — только
  для ≥18.66px/700 либо нетекстовых элементов). Добавить в CI проверку контраста
  токенных пар — она детерминирована и не требует браузера.
- **Severity:** **CRITICAL**
