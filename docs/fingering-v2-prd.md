# PRD v2: Учебный слой партитуры — «от очков к музыке»

Статус: **реализовано**, замеры и границы — в §13. Документ описывает вторую версию учебной части
вкладки «Аппликатура»: счёт такта, проигрывание под метроном, паузы и прочие
MusicXML-обозначения в интерактивном слое, расчистку легенды и показ
**единственной классической аппликатуры**. Первая версия (движок подбора, OSMD-превью,
сборка MXL) описана в [fingering-prd.md](fingering-prd.md) и здесь не
переписывается — только уточняется там, где аудит нашёл дефекты (§7).

Наследуемые правила остаются в силе:

1. **Никакого хардкода** по названию пьесы, тональности, номеру такта. Каждая
   константа выведена из партитуры либо живёт в именованной таблице с
   источником и тестом.
2. **Оригинал неприкосновенен.** Учебный слой и проигрывание работают только с
   `previewXml` в памяти; исходный `.mxl` не открывается на запись.
3. **Не выдумывать данных.** Если в MusicXML нет размера, темпа или тоники —
   интерфейс говорит «не указано», а не подставляет 4/4 и 120 BPM.

Правило, специфичное для v2: **адресат — ученик, а не движок.** Любое число,
которое ученик не может проверить за инструментом, либо переводится в слова,
либо уезжает в раздел «Диагностика».

---

## 1. Проблема

Учебный слой v1 показывает верные данные в форме, из которой ученик не может
ничему научиться.

**1.1. Счёт такта построен по фактическим атакам, а не по метру.** В
`buildRhythmCountGuide` элементы счёта создаются из множества onset. Для такта,
где на третьей доле держится половинная нота, чип «3» просто отсутствует —
последовательность выглядит как `1 · 1-и · 2 · 2-и · 3-и · 4 · 4-и`. Ученик
физически не может по такому ряду отсчитать «раз-и-два-и-три-и-четыре-и»:
пропала ровно та доля, которую труднее всего удержать. Счёт обязан быть
непрерывной сеткой, а атаки, паузы и продолжения — состояниями клеток этой
сетки.

**1.2. Ничего не звучит.** Ритм — слуховой навык. Текстовый ряд слогов не даёт
ни темпа, ни пульса, ни ощущения, что пауза — это тоже время. Нет способа
услышать такт, повторить его в цикле и подстроиться.

**1.3. Паузы невидимы для интерактивного слоя.** `noteFacts` возвращает
`undefined` для `note.isRest()`, поэтому пауза не получает ни фокуса, ни
тултипа, ни подписи для скринридера. При этом пауза — полноценный музыкальный
знак: она задаёт снятие, дыхание и вступление.

**1.4. Легенда захламлена и дублируется по станам.** Для типовой фортепианной
партитуры выводится шесть карточек, из которых три пары различаются только
номером стана: «Размер 4/4 · стан 1» и «Размер 4/4 · стан 2», две карточки
«Ключевые знаки» с одинаковым содержанием. Заголовок карточки тональности —
служебный («Ключевые знаки»), а не музыкальный («Ля мажор или фа-диез минор»).

**1.5. Альтернативная аппликатура не поддерживается целевой платформой.**
Piano Marvel отображает дополнительные `<fingering alternate="yes">`
непредсказуемо и смешивает их с основной схемой. Поэтому анализ, превью,
ресурсный MXL и PM-экспорт содержат ровно одну классическую цифру.

## 2. Цель и критерии успеха

### 2.1 Функциональные

- Счёт такта — непрерывная метрическая сетка с состоянием каждой клетки:
  **атака / пауза / продолжение / тишина**, с указанием руки для атак.
- Кнопка **PLAY** проигрывает выбранный такт: ноты обеих рук плюс клик
  метронома, с отсчётом в один такт перед началом.
- **LOOP** повторяет такт без разрыва, пока его не выключат.
- Регулятор темпа 40–160 BPM; начальное значение берётся из партитуры
  (`<metronome>`, `<sound tempo>`), а при отсутствии честно помечается как
  «темп в партитуре не указан».
- Во время проигрывания подсвечивается текущая клетка счёта и головки
  звучащих нот.
- Паузы получают фокус, тултип и aria-подпись наравне с нотами; и нота, и
  пауза сообщают, **на какой счёт** они попадают.
- Карточки ключа, знаков и размера объединены по станам; дубли исключены.
- Обозначения такта сгруппированы по учебным категориям с формулировкой
  «что делать», а не только с названием знака.
- Для каждой ноты интерфейс показывает только выбранный классический палец.

### 2.2 Педагогические

- Слоги счёта следуют реальному разрешению каждого такта: четвертное движение
  показывает только доли («раз», «два»), восьмые добавляют «и»,
  шестнадцатые — «е-и-а», тернарная доля — «раз-три-оль».
- Пауза объясняется как время, а не как отсутствие: «тишина, но счёт идёт».
- Диагностика объясняет выбранную классическую расстановку музыкальными
  правилами, а не числом очков.
- Ни один учебный текст не требует от ученика знать слова «objective»,
  «beam», «divisions», «стан 2», «voice 3».

### 2.3 Проверяемые критерии

- `bun test` — зелёный, включая новые тесты сетки счёта, состояний клеток,
  затакта, триолей, пауз, окна показа и аккомпанемента.
- `bun run typecheck` (vue-tsc) — без ошибок.
- Бенч аппликатуры по локальному корпусу (21 партитура) не ухудшает ни одну
  строку `ergonomicCostPerNote` и сохраняет 0 подавленных цифр и 0
  предупреждений.
- Согласие с авторской аппликатурой не падает: Hanon ≥ 0.75,
  учебные гаммы ≥ 0.98.

## 3. Инварианты

1. Проигрывание никогда не стартует без жеста пользователя (требование
   автоплей-политики браузеров); `AudioContext` создаётся лениво в обработчике
   клика.
2. Смена такта, смена партитуры и размонтирование компонента гарантированно
   останавливают звук и снимают все запланированные узлы.
3. Сетка счёта строится только при наличии действующего размера. `senza
   misura` и отсутствующий `<time>` дают явное сообщение, а не выдуманный 4/4.
4. Затакт показывает только реально записанные позиции конца полного такта
   (поведение v1 сохраняется).
5. Учебный слой не мутирует SVG OSMD необратимо: все добавленные атрибуты и
   классы восстанавливаются в `teardownNoteInteractions`.
6. `prefers-reduced-motion` отключает пульсацию подсветки; `forced-colors`
   заменяет свечение на контурную подсветку.
7. Альтернативные цифры и `alternate="yes"` не создаются и удаляются из
   прежних производных файлов.
8. Авторские (написанные человеком) классические цифры в режиме `fill` не
   перезаписываются.

## 4. Часть A. Метрическая сетка счёта

### 4.1 Модель

```ts
type RhythmCellKind = "attack" | "rest" | "hold" | "silent";

interface RhythmGridCell {
  offsetQuarters: number;  // от начала записанного такта
  pulse: number;           // номер доли, 1-based
  syllable: string;        // "Раз" | "и" | "три" | "оль"
  label: string;           // произносимое целиком: «Раз», «Раз-и», «Два»
  pulseStart: boolean;
  kind: RhythmCellKind;
  hands: ("right" | "left")[];
  attacksInside: number;   // сколько атак попало на этот счёт: 2 — шестнадцатые
  offGrid: boolean;        // на счёт приходится больше одной атаки
}
```

`RhythmCountGuide` дополняется полем `cells` и сохраняет `items` для
совместимости уже существующих тестов и внешних читателей: `items` — это
подмножество `cells` с `kind === "attack" | "rest"`.

### 4.2 Классический школьный счёт

Счёт строится из фактических границ нот и пауз конкретного такта. Выбирается
минимальная достаточная сетка:

- четвертное движение: **«раз два три четыре»**;
- восьмое: **«раз-и два-и три-и четыре-и»**;
- шестнадцатое: **«раз-е-и-а два-е-и-а…»**;
- 6/8, 9/8, 12/8 и триоли: **«раз-три-оль»**.

Одинаковая фиксированная строка для всех тактов запрещена: она скрывает
различие длительностей и создаёт ложное впечатление, что подсказка не связана
с нотами. Отдельный дублирующий блок «Скажи вслух» также не выводится — слоги
стоят прямо над фактическими дорожками правой и левой руки.

### 4.3 Состояние клетки

Для каждой клетки: `attack`, если в позиции есть onset звучащей ноты;
`rest`, если есть onset паузы и нет атаки; `hold`, если в позиции ничего не
начинается, но звучит нота, начатая раньше; `silent` — иначе. `hands`
заполняется из номера стана и из фактической руки, выбранной моделью
(`fingering@placement`), а не только из `staff`.

### 4.4 Что видит ученик

Одна строка непрерывного счёта. Доли — крупно и с акцентом на «раз».
Под каждой клеткой — метка состояния: атака (нота), продолжение (лига-черта),
пауза (знак паузы). Подпись человеческая: «На "три" новая нота не берётся —
звук тянется. Продолжай считать вслух.»

## 5. Часть B. PLAY / LOOP / метроном

### 5.0 Окно показа: 1, 3 или 5 тактов

Партитура рисуется окном из 1, 3 или 5 тактов (`measureSpan`), начиная с
выбранного; у конца пьесы окно сдвигается назад, чтобы экран не оставался
полупустым (`measureWindowRange`). Окно — не только картинка: счёт строится для
**каждого** такта окна отдельной строкой, проигрывание идёт сквозным временем
через все такты окна, клики метронома вычисляются по каждому такту (размер
внутри окна может меняться), а подсказки и бегунок работают на всех показанных
тактах, а не только на выбранном.

### 5.1 Источник событий

Проигрываются события, извлечённые тем же `parseXmlLite`, которым построена
сетка: `pitch → MIDI`, `onset`, `duration`, `staff`, `voice`, `rest`. Аккорды и
`backup`/`forward` уже учитываются в `parseTimedEvents`; расширяем его до
`PlayableEvent` с высотой и рукой. Форшлаги играются коротким опережением
(1/32) перед своей опорой.

### 5.2 Голос рояля

Семплы Grand Piano — это десятки мегабайт на все регистры и динамику, и они
уехали бы в бандл вкладки, которую ученик открывает ради счёта. Поэтому здесь
физически осмысленная модель рояля, а не «пианино из синуса» (Fletcher &
Rossing, *The Physics of Musical Instruments*, гл. 12):

1. **Спектр струны** задан набором амплитуд гармоник и собран в `PeriodicWave` —
   один осциллятор играет сразу весь набор обертонов. Спектры разные для баса,
   середины и дисканта: у низких струн обертонов много и они сильные, у верхних
   спектр почти чистый.
2. **Яркость гаснет быстрее громкости**: молоточек возбуждает высокие обертоны,
   которые затухают первыми. Это фильтр низких частот, съезжающий вниз; без него
   звук остаётся «электронно» ярким весь спад.
3. **Удар молоточка** — короткий шумовой всплеск (14 мс) в полосе около второй
   гармоники. Он и даёт узнаваемую атаку.
4. **Двойной спад**: перкуссивный «колен» первые 120 мс, затем длинный
   экспоненциальный хвост. Длина хвоста зависит от регистра
   (`stringDecaySeconds`): басовая струна звучит секунды, дискант — доли
   секунды.
5. **Демпфер**: снятие клавиши глушит струну за ~90 мс, а не обрывает звук.

Клик метронома деревянный, а не тональный: узкая шумовая полоса (2400 Гц на
«раз», 1750 Гц на остальных долях) не спорит с голосом рояля, поэтому доля
слышна и в густой фактуре. Частота нот: `A4 = 440`,
`f = 440 · 2^((midi − 69) / 12)`. Мастер-гейн 0.62 — аккорд из пяти голосов
рояля громче прежнего синуса и иначе клиппирует.

Честная граница: это синтез, а не сэмплированный Steinway. Тембр узнаваем как
фортепианный, но не тождествен записи инструмента.

### 5.3 Планирование и синхронизация

Расписание строится на абсолютном времени `AudioContext.currentTime`. Такт
планируется целиком; за 150 мс до его конца планируется следующий повтор, если
включён LOOP. Визуальная синхронизация — через `requestAnimationFrame`:
`elapsed = ctx.currentTime − barStartTime` → индекс текущей клетки → класс
`is-playing` на клетке и на головках нот с тем же onset. Никакого
`setInterval`-таймера как источника музыкального времени.

### 5.3.1 Бегунок по стану

Во время проигрывания по нотам едет вертикальная линия. Её геометрия строится
не по нотной математике, а по фактическим координатам отрисованных знаков
(`getBoundingClientRect` по головкам нот и паузам): между известными позициями
координата интерполируется, после последней — доводится до правого края стана.
Иначе линия разъезжается с гравировкой OSMD. Паузы участвуют в геометрии
наравне с нотами, поэтому бегунок не «проскакивает» тишину.

### 5.4 Отсчёт

Перед первым тактом — один такт клика метронома (без нот). Между повторами
LOOP отсчёт не вставляется: цикл должен быть бесшовным.

### 5.5 Темп

Начальное значение: `<metronome><per-minute>` выбранного или предыдущего
такта, иначе `<sound tempo>`, иначе 72 BPM с явной пометкой «в партитуре не
указан». Регулятор — 40…160 с шагом 4, изменение темпа во время LOOP
применяется со следующего повтора.

### 5.6 Доступность

Кнопки PLAY/LOOP — настоящие `<button>` с `aria-pressed`, состояние
проговаривается через `aria-live="polite"`. Пробел и Enter работают штатно.
`prefers-reduced-motion` оставляет подсветку, но убирает анимацию пульса.
Звук — вспомогательный канал: вся информация о такте остаётся доступной
текстом.

## 6. Часть C. Паузы и обозначения в интерактивном слое

- `FingeringNoteFacts` получает `rest: boolean`, `onsetQuarters?: number`,
  `beatLabel?: string`.
- Цель наведения для паузы — `VexFlowGraphicalNote.getSVGGElement()` (для
  нот по-прежнему конкретная головка через `getNoteheadSVGs()`).
- Тултип паузы: заголовок «Пауза», длительность, «на счёт N», рука и стан,
  пояснение «Тишина, но время идёт — продолжай считать».
- Тултип ноты дополняется строкой «на счёт N».
- Категории обозначений (артикуляция, лиги, динамика, педаль, орнаменты,
  ритмические деления) уже собираются в v1; v2 не расширяет распознавание, а
  меняет подачу — см. §7 части D.

## 7. Часть D. Расчистка карточек и легенды

- Карточки атрибутов дедуплицируются: одинаковое содержание на разных станах
  сливается в одну карточку с пометкой «оба стана».
- Заголовок карточки тональности — название тональности; служебный список
  знаков уходит во вторую строку.
- Ключ показывается одной карточкой «Скрипичный сверху · басовый снизу», если
  это стандартная фортепианная пара.
- Чипы обозначений группируются по учебным категориям; в каждом чипе — знак и
  короткое «что делать».
- Термин «стан» заменяется на «верхний/нижний стан (правая/левая рука)»,
  «мелодическая линия» объясняется одной фразой при первом появлении.

## 8. Часть E. Единая классическая аппликатура

- Движок выбирает один путь и одну цифру для каждой звучащей ноты.
- `previewXml` и ресурсный MXL сохраняют стандартную привязку цифры к ноте.
- PM-версия собирает цифры одновременных полифонических голосов одного стана
  в один `<technical>` вертикальной колонкой: Piano Marvel так не теряет
  внутренние цифры аккорда.
- Ни скобки, ни `alternate="yes"` в интерфейс и экспорт не попадают.

## 9. Часть F. Исправления по аудиту движка

1. `releaseCost` (снятие удержанного голоса) выносится из
   `parts.positionChangeCount` в отдельную статью `voiceRelease`: метрика
   «смен позиции» и учебная карточка перестают приписывать педальную передачу
   смене позиции руки.
2. `blackKeyCosts` получает пальцы соседей, чтобы правила 10 и 11 проверяли
   условие Table 1 «белая соседняя играется пальцем, отличным от большого».
3. Педагогические приоры пересчитаны по замеру, а не по оценке. Исходная
   рекомендация аудита («привести к масштабу самого дорогого эргономического
   правила», порядка −8) **опровергнута данными**: при −8 ломается канон
   фа-мажорной гаммы, а согласие с учебными гаммами падает 0.9885 → 0.9563.
   Замер по корпусу:

   | приор | Hanon | гаммы | канон в gold-тестах |
   |---|---|---|---|
   | −8 | 0.7507 | 0.9563 | ломается |
   | −12 | 0.7517 | 0.9805 | держится |
   | −16 | 0.7555 | 0.9862 | держится |
   | −20 | 0.7536 | 0.9885 | держится |

   Принято −16 (арпеджио −8, альбертиев бас −3): лучшее согласие с живой
   авторской аппликатурой Hanon при сохранении школьного канона. Причина, по
   которой приор обязан доминировать, названа прямо в коде: модель Parncutt
   одноголосно-эргономична и правил школы не знает.
4. `costPerNote` остаётся внутренней метрикой; наружу для ученика идёт только
   словесная оценка и `ergonomicCostPerNote` в диагностике.

## 9.1 Часть G. Фигура аккомпанемента и размер руки

Найдено на живом материале (Indila «Love Story», Гимнопедия Сати): фигура
«бас на сильной доле + повторяющийся аккорд над ним» не распознавалась ни одним
детектором, и чистая эргономика ставила на бас 3-й палец, а затем подкладывала
большой под аккорд. Причина: правило 6 (Weak-Finger) штрафует 5-й палец, а
модель одноголосна и не знает, что бас — это опора, с которой рука переносится
на аккорд **кистью**, а не пальцевым legato.

Реализовано:

1. Детектор `applyAccompanimentHint`: одиночный низкий звук, затем 1–3 аккорда
   над ним (не ближе малой терции), одинаковой формы, с повторением фигуры или
   с двумя аккордами внутри такта. Аппликатура выводится из интервалов самой
   фигуры: бас — крайний палец (5 в левой, 1 в правой), верх аккорда — большой
   в левой и 5-й в правой, середина — по величине промежутка.
2. Подсказка научилась задавать **форму аккорда целиком** (`Hint.fingers`), а не
   один палец: до этого аккордовые события вообще не могли получить приор.
3. Переход на аккорд отмечен как свободный перенос кисти. Фразовая лига над
   **артикулированным** (staccato) аккордом больше не требует пальцевого legato:
   это знак фразы, а не приказ связать звуки пальцами.
4. Размер кисти вынесен в UI (небольшая / средняя / крупная). Сервер умел
   `handSpan` с первой версии, но UI его не отправлял; смена размера
   пересчитывает аппликатуру. Масштабирование таблиц растяжения прямо разрешено
   статьёй Parncutt.

Замер на корпусе после включения детектора:

| партитура | эргономика/нота до | после |
|---|---|---|
| Гимнопедия Сати | 9.642 | **2.679** |
| Love Story (Indila) | 0.761 | **0.341** |
| Running Up That Hill | 4.247 | 4.108 |
| Nothing Else Matters | 1.534 | 1.432 |

Hanon 0.7555 и учебные гаммы 0.9862 не изменились, подавленных цифр и
предупреждений по корпусу — ноль.

## 9.2 Часть H. Мобильная вёрстка

- На тач-экранах `:hover` залипает после тапа, поэтому любое hover-состояние,
  меняющее геометрию, читается как скачок вёрстки. Все новые интерактивные
  элементы меняют на наведении только цвет и тень, а старые обёрнуты
  `@media (hover: hover) and (pointer: fine)`; в конце `table.css` добавлен блок
  `@media (hover: none)`, снимающий hover-трансформации и hover-тултипы.
- Подпись под названием строки больше не печатается, если автор дублирует
  название (в выгрузке Piano Marvel это сплошь slug вида
  `nothing-else-matters-metallica`): дубль удваивал высоту карточки.
- Кнопки действий в карточке приведены к 44 px — минимальной цели касания, без
  запаса в лишние 12 px.
- Транспорт счёта на телефоне перестроен в столбец: «Играть» на всю ширину,
  режимы и темп — отдельными строками.

## 13.1 Ревью покрытия корпуса

Учебный слой прогнан по **каждому такту каждой партитуры** локального корпуса
(`review-corpus`, read-only):

| проверка | результат |
|---|---|
| тактов разобрано | 1741 из 21 партитуры |
| тактов с построенной сеткой счёта | 1741 (100 %) |
| тактов без размера в MusicXML | 0 |
| нарушений инвариантов сетки | 0 |
| нот, отданных на проигрывание | 24 175 |
| тактов с темпом из партитуры | 1534 |
| альтернативных цифр в экспорте | **0** |
| нераспознанных MusicXML-знаков | 0 |

Проверявшиеся инварианты: клетки счёта идут по возрастанию времени, у каждой
непустая подпись и известное состояние, `pulseCount` совпадает с числом долей,
`items` содержит только атаки и паузы, в объяснении нет `undefined`/`NaN`, все
высоты для проигрывания лежат в диапазоне рояля, длительности положительны, ни
одна нота не выходит за границу такта.

Найденные ревью дефекты и что с ними сделано:

1. **Piano Marvel терял цифры полифонических аккордов.** Добавлен отдельный
   PM-экспорт с вертикальной колонкой одновременных цифр (§8).
2. **Окно из пяти тактов разбиралось пять раз на каждый шаг листания.**
   Добавлен кеш учебных данных по номеру такта (`learningCache`, 64 такта, FIFO).
   Замер на «Clocks» (161 такт): разбор одного такта 3.9–5.3 мс, окно из пяти
   без кеша 19 мс, с кешем шаг стоит один разбор ≈ 4 мс. Документ при этом
   парсится один раз на партитуру, а не на такт.
3. **«1/8 целой» вместо «восьмая»** — когда в MusicXML нет `<type>`, OSMD отдаёт
   `NoteType.UNDEFINED`, и тултип печатал служебную дробь. Название теперь
   выводится из доли целой (`FRACTION_DURATION_LABELS`), а совсем нестандартная
   длительность честно называется «доля 5/16 целой».
4. **Служебные подписи в тултипе** — убран номер стана из «верхний стан (1)», а
   строка «Мелодическая линия 1» показывается только там, где голосов
   действительно несколько.
